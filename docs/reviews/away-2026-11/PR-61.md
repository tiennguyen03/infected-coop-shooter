## What it does

Behind the Call-ins desk in the lobby there is now a row of pallets with every call-in on
display (the Doorman sentry, mines, the Shrike and so on). Choosing option 1 at the desk moves
the camera along the row; hovering lifts a piece, clicking shows its card with a BUY button, and
each pallet's plate shows its price or "ON YOUR RECORD".

## Findings

1. **The plates go blank after a respawn** (sure). Each plate's text is a `SurfaceGui`
   placed in the player's screen folder (`PlayerGui`), and it is not told to survive a
   respawn (`ResetOnSpawn` stays at its default, true),
   `src/lobby/client/CallInDisplayUI.luau:296-311`. When the character respawns, Roblox
   deletes them. The script still remembers each id in `statusLabels` and skips it next time
   (line 293), so the plates are never rebuilt. Trigger: Esc → Reset Character in the lobby, then
   look at the pallets. Fix: `surface.ResetOnSpawn = false` (other lobby UI already does this).
2. Possible, small: two display pieces (the Doorman and the ammo crate) pick a stand-in part as
   their anchor; when the real meshes load, that part is deleted
   (`src/lobby/server/CallInDisplay.luau:94-97, 505`). If the swap happens while a player is
   hovering that piece, it may end up slightly out of place. Only while meshes are still loading.
3. Small: the plates reuse the `RackDisplay` attribute (`CallInDisplay.luau:545`) to hold a
   call-in id, while elsewhere it means "wall", "counter", or a gun id. Nothing breaks today; a
   new attribute name in `Attributes.luau` would be clearer.
4. Small: fallback numbers in code repeat Config values (`CallInDisplay.luau:223, 232-233`:
   the Shrike rotor hub and Doorman heights). Drop them and read Config.
5. Docs: the file table in `docs/sprints/LOBBY_V1_FALLOW.md` does not list the two new files
   `CallInDisplay` (server) and `CallInDisplayUI` (client).
6. Possible, needs a look: the board said to be "on the hull" sits at X about 32.7 while the
   hull is at X 35, so it may float about 2 studs off the wall.

Fine: no new remotes. BUY uses the existing server buy, which checks money and price. The
camera, hover and plates are local to each player, so four soldiers can browse at once, and
leaving the desk gives the camera back. About 130 still parts, one small light with shadows off:
within the budgets in `docs/STYLES.md`. Each call-in's `Display` values sit on its own Config
row with defaults, as the project rules want.
