# PR #56: Call-ins land on crowds: the mark holds the Infected on it (not yet played)

- Author: tiennguyen03 (branch `claude/callins-land`)
- Head commit reviewed: `14a61057db53a42980ac34e8b61b82686df66b7c`
- Reviewed: 2026-11-17 (by reading the code; the tests were not run here)

**Verdict: Looks safe to merge** (nothing breaks; how strong the hold should feel is a
playtest question).

## What it does

When you throw a Hammer, Anvil or Shrike, the Infected near the mark now walk onto it and stay
until the first round lands, instead of chasing you out of the blast. Blasts (fire missions and
the Tripline mine) are now measured flat across the ground, up to 8 studs up or down, instead of
as a ball from the centre.

## Findings

1. **Pausing ends the hold early** (sure; solo only, since pause is a solo feature).
   `src/server/AirStrikeService.luau:80-85` starts the hold with `EnemyService.setLure(...,
   seconds)`, and the lure's end time is real time (`os.clock()`,
   `src/server/EnemyService.luau:1540-1548`). The shells themselves wait with `waitUnpaused`,
   which stops counting during a pause. Trigger: solo, throw a Hammer, pause for 4 seconds,
   unpause: the hold has already run out, so the crowd walks out before the shells land, the
   exact thing this PR fixes. The Resupply flare's lure already had this flaw. Smallest fix: in
   `hold()`, `task.spawn` a `waitUnpaused(seconds)` and then remove that lure, instead of
   relying on the clock.
2. **Possible "panic button"** (design, the author flags it too). Any chasing melee Infected
   within 16 studs of the mark turns round and walks to it for about 5 seconds, and there is no
   friendly fire. A soldier surrounded by Infected can throw a Hammer 8-10 studs away and the
   whole pack leaves them. Possible fix if it feels cheap: no hold when a living soldier is
   inside the blast, or a smaller `Hold`.
3. **Walk It In and the hold pull opposite ways** (sure about the numbers, the effect is
   a feel question). The hold always pulls the crowd onto the mark (`AirStrikeService.luau:247`),
   but with the Walk It In upgrade the 6 shells land 0, 8, 16, 24, 32 and 40 studs along the
   throw (`StrikePattern.offsets` with `centred = false`). Only the first 2-3 shells reach the
   held crowd; the hold ends after shell 3 (`HoldAfter = 2`). Possible fix: hold at the middle
   of the walk when the upgrade is on.
4. **The tests check a copy, not the game** (sure). In `tests/StrikeLanding.spec.luau` the
   "20 of 20 held" tests run their own copy of the lure logic and never call the code the game
   uses. The game also measures the hold distance in 3D, the test flat, so a tall Infected like
   the Brute is held from a bit less than 16 studs. Not covered: radius 0, height 0, below the
   ground. Fix: move the hold distance check into `Rules/StrikeLanding` and have
   `EnemyService` use it, then test that.
5. Docs say more than the code does (sure, small). `docs/PROGRESSION.md` says the mark "holds
   the Infected"; the code holds only melee forms that are already chasing. Hockers (who spit),
   sleeping Infected, climbers and the Warden are not held. One phrase in PROGRESSION fixes it.
6. Behaviour change not written down (possible, small). Because blasts are now flat with an 8-stud
   height, a Hammer or Anvil no longer hits Infected on a roof more than about 8 studs above the
   impact (the old ball of 12 or 20 studs did), and a Tripline can go off from an Infected one
   floor up.
7. Style nit: `src/server/MineService.luau:6` is a 131-character comment line (the limit is 100).

Fine: Bosses and spitters skip the hold (`EnemyService.luau:1160-1166`); every lure expires
and is cleared when a run resets, so no Infected stays stuck; it never changes WalkSpeed or
anchors anything; each call-in has its own `Landing` row with defaults, as the project
rules want; no new per-frame loop.

   too easy (finding 2)?
4. With Walk It In, Hammer a crowd and compare kills with the plain Hammer (finding 3).
5. Anvil a group on a rooftop: does it still kill them (finding 6)?
