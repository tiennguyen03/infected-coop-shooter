## What it does

It rebuilds the lobby ship in Blender as a "before" and a revamped "after": frames, pipes and
doors in the hangar, each desk dressed as a place, deck gear, a burning city off the port side
and 12 Easter eggs. It adds 63 preview pictures and a design page,
`docs/sprints/CARRIER_V2.md`, with a step list for building it in the game and four questions.

## Findings

1. Fine: no file under `src/` or `tests/` changes. The new pieces only build when the asset
   build is run with `--carrier-v2` (`assets/3d/build/build_assets.py:1386-1392`), so a normal
   build is unchanged.
2. **Over the drawing budget, and it says so.** The page measures the v2 ship at about 49,500
   triangles drawn against today's 16,600 and the 18,000 ship cap in `docs/STYLES.md`, plus a
   24,000-triangle city. The cuts are listed, but none is decided. This matters most on phones
   (frame rate on low-end devices counts as playability in this project). Run the
   performance-reviewer before approving.
3. **Size:** the 63 pictures add about 77 MB to the repository (main already holds about
   155 MB of preview pictures). Everyone who clones the project downloads them forever, even
   if the look is rejected. Smallest fix: keep a handful of before/after pairs in the
   repository and leave the rest on the Desktop folder.
4. Small: the Blender script saves `assets/3d/carrier_v2.blend`
   (`assets/3d/build/carrier_v2.py:46`), and `.gitignore` does not list it (it lists the other
   two `.blend` files by name). A `git add -A` would commit a large file. Fix: add
   `assets/3d/carrier_v2.blend` to `.gitignore`.
5. The step list depends on #55, #57 and #61 merging first, and their names (`Spot.sign`, the
   `callins` desk, `FallowLayout.CallInDisplay`). If any of those changes before merge, the
   step list needs the same change.
6. Lore flag, as the page says: the burning city is not on the world map yet; the lore
   developer adds it only after the owner approves.
