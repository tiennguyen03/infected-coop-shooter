## What it does

In the lobby your soldier now stands and walks with the same rifle animations as in the
match and holds the rifle you picked at the Loadmaster. To do this, the walk/run animation
code was moved out of the match's `AnimationController` into a shared file both places use.

## Findings

No blocking bug found.

1. **Heads-up for Nova: the PR changes the lobby.** `src/lobby/server/PikeBody.luau`,
   `src/lobby/server/LoadmasterService.luau`, `src/lobby/client/Main.client.luau` (one line)
   and the new `src/lobby/client/SoldierMoves.luau`. The handoff note tells Nova and names
   the off switch (`Config.Lobby.Soldier.Enabled = false`).

2. **Possible: after a respawn in the lobby, the default Roblox animations may play on top
   of the new ones.** `src/lobby/client/SoldierMoves.luau:72-75` turns off Roblox's own
   `Animate` script only if it is already there, without waiting for it. The match waits up
   to 3 s for the same thing (`src/client/AnimationController.luau:212`).
   Trigger: fall off the deck in the lobby, respawn, walk: doubled or mushy animation.
   How sure: possible (depends on the order things arrive). Smallest fix:
   ```lua
   local animate = character:FindFirstChild("Animate") or character:WaitForChild("Animate", 3)
   ```

3. **Small: the Loadout request has no rate limit, and each accepted one now rebuilds the
   rifle for everyone.** `src/lobby/server/LoadmasterService.luau:83-97`: the request is
   checked properly (valid loadout, guns owned), but can be sent every frame. With this PR a
   change of main gun also destroys and rebuilds the rifle model (`:49-52`,
   `PlayerSetup.attachRifle`). A cheater who owns two main guns could flip between them
   every frame to make work for the server. Nothing is gained. How sure: verified by reading.
   Smallest fix: ignore requests less than 0.5 s after the last one from the same player.

4. Trivial: the comment at the top of `src/lobby/client/DefaultStepMute.luau` says the
   lobby does not have the match's walk animations yet. It now does.

Checked and fine:
- The match's walk, run, strafe, crouch and prone animation logic was compared line by line
  with `main`: thresholds, weights, fade times and respawn resets are the same.
- The lobby place includes the shared folder, so the new shared files exist there.
- A player cannot hold a gun they do not own: the only way to change it is the existing
  Loadout request, which checks ownership on the server. No new messages were added.
- The rifle is rebuilt on each respawn without duplicates and removed on death.
- If the animations fail to load, the lobby falls back to Roblox's default ones after 8 s.
- The lobby is type-checked by its own step in CI (`.github/workflows/ci.yml`).
