# PR #69: Objective progress you can't miss, and a HUD that doesn't stack

- Author: tiennguyen03 (branch `claude/objective-progress-visible`)
- Head commit reviewed: `91b73310819701689cf16f4cce7ae758e9097f89`

**Verdict: Fix first** (one small fix: every extraction now starts with a red "PAUSED" bar).

## What it does

The line at the top of the screen that says what to do now has a progress bar under it, saying
"HOLDING 23 of 60s" in yellow while the squad holds a zone, or "PAUSED" in red when nobody
is holding. The squad panel and the objective list on the left are stacked so they no longer
overlap.

## Findings

1. **Every extraction shows a red "RETURN to the LZ · PAUSED 0 of N" before anyone has
   reached the pad** (sure). The server sends "Returning" every sync while nobody stands on the
   pad, even when the hold never started (`src/server/ExtractionService.luau:153-157`), and
   the new UI turns that into a red PAUSED bar at 0
   (`src/client/ExtractionUI.luau:41-48`). So "REACH the LZ" shows for a moment and then the
   squad is told off for pausing a hold they never began. Smallest fix: in `ExtractionUI`, when
   progress is 0, show the plain "REACH the LZ" line with no bar.
2. **Joining mid-hold shows a false red PAUSED for about a second** (sure, small).
   `trackProgress` (`src/client/ObjectiveUI.luau:202-209`) remembers the first count but
   not when it went up, so `meterReadout` (line 216) treats it as "never went up" → PAUSED.
   Fix: if there is no time yet, show the plain count.
3. Possible: when the bar switches between the main and a side objective (for example right
   after a Spitter kill), the fill slides from one objective's amount to the other's, which can
   look like the hold went backwards (`MissionLine.luau` around lines 99-112). Fix: snap the fill
   when the objective changes.
4. Small: only with objectives turned off (the old fallback hold), the bar says HOLDING even
   when nobody is in the zone. Objectives are on by default.
5. Cosmetic: when the line clears, the text fades but the bar stays solid for 0.3 s, then
   vanishes.
6. Older, possible: a new subtitle that arrives during the previous one's fade can stay invisible
   (`BuffNoticeUI.luau:126-147`, the old fade keeps running).
7. The header comment of `ObjectiveUI.luau` (lines 5-11) still describes the old layout.

Fine: no server change. The Warden's part of the objective shows correctly (the bar hides for
"kill the Warden" and reads PAUSED when he blocks the hold). A restart clears everything.
No new per-frame work or leaks. Tuning is in Config; the new rule has tests.
