## What it does

The health bars and name tags floating over Infected, players and bots are turned off. A new
panel on the left of the screen shows each squadmate (player or bot) with health, armour,
DOWN with the bleed-out countdown, REVIVING, or DEAD with the respawn countdown.

## Findings

1. **A bot removed while it is reviving someone leaves "REVIVING" stuck on that person.**
   `src/server/BotService.luau:698-705` (`removeBot`) does not call the new
   `stopReviving(bot)` (`:151-156`). The squad panel then shows a full blue "REVIVING" bar
   with no bleed-out countdown while the player is in fact bleeding out, and the downed
   player's own screen keeps saying "PIKE FOUR is reviving you".
   Trigger: solo with bots, go down, and a second player joins while the last bot is
   reviving you (a bot is removed to make room). The dev panel's bot count does the same.
   How sure: verified by reading. Smallest fix: add `stopReviving(bot)` in `removeBot`
   before `despawn(bot)`.

2. **A bot knocked over (or dodging the Warden) mid-revive also leaves the bar on
   "REVIVING".** `src/server/BotService.luau:550-551` and `:577-578` return before the code
   that clears the label. The bar fills to 100% and sits there, hiding the bleed-out seconds.
   Trigger: Warden fight, a bot starts a revive, the Warden knocks the bot down.
   How sure: verified by reading. Smallest fix: call `stopReviving(bot)` in both branches.

3. Possible: a downed or dead player holding the revive key near another downed body shows
   a "REVIVING" bar that never completes (`src/server/Squad.luau:485-487` does not check
   that the holder is alive; the actual revive at the end is checked). Depends on whether
   Roblox shows the prompt to a downed player.

4. Docs: `handoff/README.md` on this branch says "revive (hold E)". The code uses F
   (`Squad.luau:479`). Same mistake as in #22; only right if #40 merges first.

5. Small: the bot's revive bar ends about one tenth of a second before it looks full
   (`BotService.luau:462-466`). Cosmetic.

6. Small, possible: a player who joins mid-run can get the same callsign as a bot (for
   example two "Pike Two") until the next run; the reviver is matched by name
   (`Squad.luau:134-138`), so their revive labels can mix. Display only.

Checked and fine:
- The server only sends squad data when something changes (health in whole numbers, state
  changes), not every frame.
- The data lives in `ReplicatedStorage.SquadRoster`, not on the bodies, so the panel still
  works when a squadmate is too far away for their body to be loaded.
- Countdowns use the server's clock, so every player sees the same seconds.
- Joining late, leaving, respawning, restarting and changing the bot count add and remove
  rows correctly, in the same order for everyone; you never see your own row.
- The floating bars are turned off for players and bots on every respawn; the Warden's bar
  at the top still shows. A `Config` switch brings the floating bars back.
- No new messages from players; names go through `Attributes`; the rule has a test file.
