# PR #39: Revive animation: kneel, sling the rifle, press a dressing, pull them up

- Author: tiennguyen03 (branch `claude/revive-animation`)

- Reviewed: 2026-11-11 (by reading the code; the tests were not run here). This is almost

**Verdict: Looks safe to merge** (small cosmetic fixes; needs a two-player look).

## What it does

A revive now has an animation for both people, players and bots: the reviver slides to a
kneeling spot beside the downed soldier, slings the rifle, presses a dressing and pulls
them up; the downed soldier lies on their back and then gets up. The revive rules (hold 3 s,
within 8 studs) are unchanged, and the revive still completes on the server whether or not
the animation finishes.

## Findings

No path was found that leaves a reviver stuck: the PR never freezes a body, never changes
walk speed and never joins the two bodies together.

1. **Possible: the slide to the kneeling spot can pass through a thin wall.** The server
   checks the straight line from where the reviver stood when the hold began
   (`src/server/ReviveAnimService.luau:115-154`). But the slide only starts once the reviver
   stops moving, from wherever they are by then, and it is a plain position change with no
   collision (`src/shared/ReviveAnimation.luau:141-146`, `:225-228`; `MaxNudge = 8` studs).
   Trigger: a downed body near a door frame or thin wall; start the hold with a clear line,
   keep walking round the corner while holding, then stop: you are slid through the wall to
   the kneeling spot (which is itself a valid spot).
   How sure: the logic is verified by reading; whether the map has such a place is not.
   Smallest fix, in `stepDriver`: if the reviver moved, do not slide, only turn:
   ```lua
   if phase == "walk" then
       driver.nudged = true
   end
   ```

2. **You can fire while the rifle is slung on your back, and the shot leaves from your
   back.** The rifle is moved to the torso on each player's screen
   (`ReviveAnimation.luau:575-577`), and the shot starts from the rifle's muzzle
   (`src/client/WeaponController.luau:189-191`). Firing is only blocked when downed or
   knocked (`:169-176`), not while reviving.
   Trigger: third person, hold the revive key, wait 0.3 s, click fire: the tracer comes from
   behind your shoulder and can hit a wall behind you. How sure: verified by reading.
   Smallest fix: block firing (or start the shot from the body) while the character's
   `ReviveRole` is "treat"; or set `Config.ReviveAnimation.SlingRifle = false`.

3. Small: a reviver knocked down by the Warden mid-revive keeps kneeling with arms out
   instead of falling (`ReviveAnimService.luau:302-307` treats "knocked" as still alive).
   Cosmetic.

4. Docs: `docs/PROGRESSION.md` and `handoff/README.md` on this branch say "hold E"; the code
   still uses F until #40.

5. Small, project rule: a handful of numbers are written in code instead of `Config`
   (`ReviveAnimService.luau:32-33, 126, 141`; `ReviveAnimation.luau:33-34`), and the new
   service keeps its sessions without registering with `Lifecycle` (it does clean itself
   every frame, so no leak was found).

6. Possible, cosmetic: the "body does not turn with the camera" lock is one shared on/off
   switch also used by vault, roll and slide; a revive ending during a vault can unlock it
   early.

Checked and fine:
- No new messages between players and server: the server sets attributes, each machine
  plays the motion. Nothing a cheater can use.
- Every way a revive can end was traced (key released, revive completes, someone else
  finishes first, reviver downed or killed or gone, casualty bleeds out, too far, run
  restart, a bot interrupted): in each, the kneel stops, the rifle returns to the hand and
  the body turns with the camera again.
- Only the reviver is moved, at most 8 studs, and only on a spot the server checked for
  walls, floor and space. The downed body is never moved.
- No new animation uploads: it reuses three existing clips; a missing clip is skipped
  without errors. A `Config` switch turns the whole feature off.
- Two revivers on one body kneel on opposite sides.
- Cost: a few attribute reads per frame for bodies taking part; no lights or particles.
