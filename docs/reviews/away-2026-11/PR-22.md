# PR #22: Bots walk to the leader and use stims, frags and fire missions

- Author: tiennguyen03 (branch `claude/bots-walk-consumables`)
- Head commit reviewed: `943f899c5297320a0756cf10e3e4029d5cc64d2d`
- Reviewed: 2026-11-11 (by reading the code; the tests were not run here)

**Verdict: Fix first** (no crash or cheat found; bots can waste their grenades and fire
missions, and it clashes with #18).

## What it does

Bots now walk (or find a path) to a spot behind the nearest standing player instead of
teleporting, and only teleport when stuck far away. They also use their own stims, frags and
one Hammer or Anvil each, and in a boss fight they spread out and dodge.

## Findings

1. **A bot's frag or fire mission can land at your feet (wasted, but it cannot hurt you).**
   The bot checks its throw line with a ray that ignores all players and bots
   (`src/server/BotService.luau:322-353`, used at `:838-856`). The real throw does not ignore
   them: a frag stops on any player or bot in the way (`src/server/KitService.luau:148-151`),
   and a fire mission stops on a player (`src/server/CallInService.luau:119-128, 203-204`).
   A throw that hits something lands 2 studs short of it (`src/shared/ThrowUtil.luau:28-29`).
   Bots stand behind the leader (`Config.Bots.Slots`), so the leader is often on that line.
   Blasts only damage Infected, so nobody is hurt, but the bot loses one of its 3 frags or
   its only fire mission, and the docs promise this never happens
   (`docs/MULTIPLAYER_READINESS.md`: "never thrown with any squad member ... inside the blast").
   Trigger: solo with 3 bots, stand still facing 4+ Infected 20-30 studs away so a bot is
   right behind you; watch for the frag ring at your feet.
   How sure: verified by reading. Smallest fix: in the bot's `tryThrow`, work out the real
   landing point with the same exclusions the throw uses and refuse the throw if it is more
   than 3 studs from the intended point; or let bot throws pass through players and bots.

2. **After #18 and #22 are both merged, a bot's Hammer or Anvil arrives with no warning mark
   and no whistle.** #18 moves the ground marks and the incoming sound to the players'
   machines, triggered by a message that only `CallInService.fire()` sends. This PR's
   `CallInService.fireMissionFor` (`:192-209`) calls `AirStrikeService.fireMission` directly
   and never sends that message. The bot's radio line says "Stay clear of the mark" and
   there is no mark.
   The two PRs also conflict as text in `src/server/AirStrikeService.luau` (and
   `docs/HISTORY.md`), confirmed with a trial merge.
   How sure: verified by reading both branches. Fix on whichever merges second: in
   `fireMissionFor`, send the `CallInArrival` message with the impact points, and check the
   client code accepts "no thrower".

3. **Possible: bots ask for a new path every second, forever, when they cannot reach you.**
   `src/server/BotService.luau:745-761`: a failed path leaves no waypoints, which counts as
   "stale", so it is requested again every `PathInterval` (1 s) per bot. Bots cannot jump or
   climb (`:587-588`), but players can.
   Trigger: climb onto something bots cannot reach, 8 to 30 studs from them (nearer than the
   30-stud teleport distance), and stay there: 3 failed path searches a second while the bots
   walk into the obstacle. The same can happen in a boss fight when a bot's post is inside a
   wall. How sure: the loop is verified by reading; the cost needs measuring.
   Smallest fix: wait longer after each failure, for example
   `now - bot.pathAt >= settings.PathInterval * math.min(1 + bot.pathFails, 5)`.

4. Small: the bot's radio line is shown as spoken by "Control"
   (`src/client/BuffNoticeUI.luau:153`), so it reads "Control: Pike Two: Hammer on the way"
   (`BotService.luau:897-900`, `Config.luau:203`). Drop the `%s:` prefix or pass the speaker.

5. Small, docs: this PR changes `handoff/README.md` to say "revive (hold E)". The code still
   uses F (`src/server/Squad.luau:424`); E is the stim. Change the word back to F (unless
   #40, the keyboard layout PR, merges first: it moves these keys).

Checked and fine:
- No friendly fire: frags and fire missions damage only Infected.
- A bot is never passed into code that needs a real player; nothing is sent to a non-player.
- The player's own stim and grenade code keeps every check it had.
- Bots use their own stims, frags and cooldowns; they never take a player's.
- A run restart rebuilds every bot's state; a path search that finishes late is ignored.
- With 2-4 players each bot follows the nearest standing player and re-picks when that
  player goes down or leaves; with no player it stands and shoots.
- Bot thinking runs 10 times a second, not every frame; numbers are in `Config.Bots`; the
  decision rules are pure with a test file.
