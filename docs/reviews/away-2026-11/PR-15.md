# PR #15: Rewards that land, a 60 s extraction with a second wave

- Author: tiennguyen03 (branch `claude/rewards-extraction`)
- Head commit reviewed: `8ad333e57c4edad1a232a4dcbfc4e1f8dabc075e`
- Reviewed: 2026-11-11 (by reading the code; the tests were not run here)

**Verdict: Fix first** (small fixes; no crash and no cheat found).

## What it does

Guns start with about half their spare ammo, and a second "FIELD KIT" crate with upgrade
cards drops when the hold objective is finished (the Warden's pallet now gives supplies).
Extraction takes 60 s instead of 30 s, with a second wave of Infected at the 30 s mark.

## Findings

1. **A player who is downed when the hold ends gets no upgrade cards from the new crate.**
   `src/server/RequisitionService.luau:233` and `:259-272`: cards are offered once, only to
   players who are standing at the moment the crate lands (`livingPlayers()` =
   `Squad.livingOwners()`). `onPick` (`:370-374`) refuses anyone without an offer. The new
   crate is dropped from `src/server/ObjectiveService.luau:107-113`, right at the end of the
   45 s hold, which is when someone is most likely to be down.
   Trigger: two players. One goes down in the last seconds of the hold. The crate lands; the
   standing player gets 3 cards, the downed one gets none, even after being revived 3 s
   later. A player who joins late has the same problem.
   How sure: verified by reading. (The once-only offer already existed on `main`; this PR
   moves a crate to a worse moment for it.)
   Smallest fix: in `RequisitionService`'s per-step loop over crates and living players
   (`rearmNearby`), give an offer to any living player who has none yet:
   ```lua
   if crate.offers[player] == nil then
       local choices = offerFor(player, crate.kind)
       crate.offers[player] = choices
       if #choices > 0 then
           resupplyRemote:FireClient(player, Messages.Resupply.Cards,
               crate.id, crate.kind, choices, crate.cardPositions)
       end
   end
   ```

2. **Possible: the two upgrade crates can show the same card, and picking it twice wastes
   the second pick.** Cards stay up for 60 s (`Config.luau:803`, `CardLifetime = 60`) and the
   hold takes 45 s (`Config.luau:1004`), so the first crate's cards are usually still up when
   the second crate lands 10 studs away. `LoadoutService.giveUpgrade`
   (`src/server/LoadoutService.luau:527-541`) returns true even when the player already holds
   that exact upgrade, so `RequisitionService.applyCard` (`:334-337`) counts the pick as used.
   Trigger: take card X at the first crate, then card X at the second: "took X" is announced
   and nothing is gained.
   How sure: the code path is verified; whether the same card is rolled at both crates depends
   on luck and the size of the upgrade list.
   Smallest fix, in `applyCard`:
   ```lua
   if definition.Kind == "upgrade" then
       if LoadoutService.hasUpgrade(player, cardId)
           or not LoadoutService.giveUpgrade(player, cardId) then
           return nil
       end
   ```

3. Small, comment only: `LoadoutService.luau:72-74` (`fullGun`) and the comment "a newly
   picked gun starts full" are out of date; a gun now starts with half its spare ammo. This
   also means changing guns in the Arms Room mid-mission drops spare ammo back to half.
   Decide whether that is wanted.

Checked and fine:
- The extraction timer resets properly on a restart; the second wave fires exactly once at
  30 s of progress, even if the squad steps off the pad and back; nothing fires after a wipe.
- The wave size scales with the number of living players (12, +3 each), not a fixed player.
- No new messages from a player's machine to the server; picking a card is still checked on
  the server (alive, close enough, one pick per crate, card was offered).
- The new numbers are in `Config`, the wave rule has its own test file, and the docs match
  the code (60 s, wave 12 +3, chest plate 400).
