- Reviewed: 2026-11-11 (by reading the code; the tests were not run here). Only Nova's six

**Verdict: Fix first** (the mission always starts, but every run now begins with 20 s that
cannot really be skipped; it also adds a rule to `docs/OWNER.md` in Nova's name, and it
targets `main` with #48 and the integration branch inside).

## What it does

At the start of a mission the screen is black, then a 14.5 s cutscene plays: the helicopter
flies in, hovers over the landing zone, the squad jumps out, and it flies away. Each
player's machine plays it by itself with stand-in copies of the squad; the real soldiers
are hidden and cannot move or shoot until it ends.

## Findings

1. **Skipping does not shorten the wait, and it replays on every run.** The server now
   holds the landing phase for 2.5 + 14.5 + 3 = 20 s instead of 3 s
   (`src/server/RunManager.luau:97-112`; `Config.Insertion.LeadSeconds`, `Seconds`,
   `Run.InsertSeconds`). Pressing Space or the A button
   (`src/client/InsertionCutscene.luau:751-754`) only ends the picture on that player's
   screen: the objectives and the Infected still arrive at 17 s and 20 s. The same happens
   again after every wipe and READY. There is no "skip" hint on screen and no skip on touch.
   Trigger: solo, press Space after 1 second: you stand on the pad for about 19 s with
   nothing to do. How sure: verified by reading.
   Smallest fix: only play it on the first run of a server (the client already skips when
   the start time is old); otherwise use the old 3 s.

2. **The HUD can show on top of the cutscene.** The cutscene hides the HUD by turning off
   the screen elements that exist at that moment, once
   (`InsertionCutscene.luau:172-183`, called at `:403`). But it starts 5th in the client's
   boot list, before the health bar, objectives, squad panel and the rest are built
   (`src/client/Main.client.luau:8` against `:19-42`). On a fresh server the run is already
   "landing" when the client starts (Nova's own note says so), so those elements appear
   afterwards and are never hidden.
   Trigger: solo direct join, or the first run on a new server: look for the health bar or
   timer during the flight. How sure: the one-time snapshot is verified; whether it shows
   depends on start-up timing. Smallest fix: hide new HUD elements every frame while playing.

3. **Possible: if the cutscene code hits an error, the player is left on a black screen,
   unable to move or shoot, for the rest of the mission.** The black cover, the "held"
   state and the camera are only released in `finish()`, which is only reached from the
   per-frame loop set up at the end of `play()`; nothing protects the code in between
   (`InsertionCutscene.luau:344-649`), and the cover refuses to lift while `playing` is true
   (`:125`). No actual error was found by reading, but this code is new and one error here
   costs the player the whole mission. Smallest fix: run `play()` under `xpcall` and release
   everything on failure.

4. **Decision: `docs/OWNER.md` is changed in Nova's name.** The file says every rule in it
   comes from the owner. The existing rule reads "Transitions are a fade, not a loading card
   ... fade in on the pad with the drop-off sound ... No custom ride card or teleport screen
   for now. (2026-11-09)". This PR keeps that and adds: "**The arrival is a cutscene**
   (2026-11-11, Nova: ...) ... skippable". The two sentences now contradict each other, and
   "skippable" is not really true (finding 1). Tien should confirm or reject this before it
   merges. (Small: the cutscene is called "the Lantern" here, while #30 renames it "the
   helicopter" for players.)

5. Small: with four squad members, the last soldier's real body appears on the pad about
   0.1 s before their stand-in lands (`InsertionCutscene.luau:712`): a brief double.

6. Small, performance: during the cutscene the code walks every part of every squad body
   each frame and keeps a smoke emitter running continuously for about 5 s (roughly 100
   large sprites near the camera). `docs/STYLES.md` asks for short bursts, not continuous
   emitters. It only lasts 14.5 s with no enemies alive, so the risk is a stutter on weak
   devices. Not measured.

7. Small: the mission timer and the difficulty clock keep running during the extra 17 s, so
   the timer reads about 0:20 when you first get control. On a READY restart a stand-in can
   be copied from the old dead body if the respawn is slow (possible).

8. Small, project rules: many camera and dust numbers are written in the client file
   instead of `Config`; the timeline maths has no test file.

Checked and fine:
- The mission always starts: the timing belongs to the server, and no player can delay or
  skip it for the others. No new messages from players.
- A player who crashes, leaves or joins late does not affect the run; a late joiner jumps
  to the right moment of the cutscene or gets none.
- No Infected spawn and nothing can hurt you while the screen is black or you are held.
- Real soldiers are not frozen in place or moved, only hidden on your own screen, and are
  shown again at the end. The stand-ins exist only on your machine, are not counted as
  squad or enemies, and are destroyed afterwards, together with the helicopter, sound and dust.
- `Config.Insertion.Enabled = false` turns the whole thing off and restores the old 3 s start.
