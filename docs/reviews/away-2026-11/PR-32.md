## What it does

It adds a small readout (a medal with your merits, a steel tag with your tabs) to the top of
the lobby screen and to the results screen after a mission, where the merits count up to the
new total. The match server now also tells each player's screen what their saved balance is.

## Findings

1. **Small: after a quick restart, the next results screen can start from a wrong number.**
   `src/server/MeritService.luau:67-72` (`publish`) and `:137-143`: when the save finishes,
   the balance is put on the player if they are still in the server, without checking that
   it is still the same run. If the player presses READY before a slow save returns, the
   reset clears the balance (`:165-169`) and the late save puts it back; it then stays for
   the whole next run. At the next results screen the "ON YOUR RECORD" row appears at once
   and starts counting from too low a number; if that run's save fails, the row stays next
   to "MERITS NOT SAVED" instead of hiding.
   Trigger: a Studio or direct-join match (where READY restarts in place), win, press READY
   straight away while saving is slow, finish the next mission. It cannot happen for a squad
   that flies home to the lobby.
   How sure: verified by reading. Display only: the saved merits are right.
   Smallest fix: count the runs and ignore a save from an older run:
   ```lua
   local payRun = 0
   -- in pay(), before the loop:      payRun += 1; local run = payRun
   -- in the spawned function, after `pending -= 1`:  if run ~= payRun then return end
   -- in Lifecycle.register:          onRunStart = function() payRun += 1 end
   ```

2. **Possible: the two icons may show late, or as a placeholder.**
   `src/shared/Config.luau:222-223` uses thumbnail links (`rbxthumb://type=Asset&id=...`)
   because the real image ids were never looked up (`uploaded_ids.json` has `"imageId":
   null`; the PR's docs say so). Thumbnails load more slowly than normal images and may not
   keep the see-through background. How sure: possible; needs eyes in Studio.
   Fix: look up the image ids and use `rbxassetid://<id>` in `Config.Wallet`.

3. **Heads-up for Nova: a new lobby file.** `src/lobby/client/WalletUI.luau` (36 lines) and
   one line in `src/lobby/client/Main.client.luau`. The readout sits in the lobby's top bar
   and may overlap Nova's screens; the rack and desk panels still print their own
   "N MERITS · N TABS" line, so the balance shows twice.

4. Small, project rule: two colours are written inside `src/shared/WalletReadout.luau:21-22`
   instead of `Config`.

Checked and fine:
- No extra save-service calls when a mission pays: the balance comes back from the save
  itself. A mission that pays 0 does one read per player.
- If the save or read fails, no balance is shown (apart from finding 1), so the screen never
  shows merits that were not saved.
- The balance attributes are only set by the server. No new messages from players.
- Number formatting handles negative, missing and huge values ("12.4k", "999B+"), with tests.
- The shared readout only uses modules that exist in both the lobby and the match.
- The icons come from the generator (`assets/icons/build/icons.js`); re-running it gives
  identical files.
