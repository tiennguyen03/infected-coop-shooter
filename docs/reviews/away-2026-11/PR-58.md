# PR #58: The Warden is the main objective's last act

- Author: tiennguyen03 (branch `claude/boss-in-objectives`)
- Head commit reviewed: `754240cf74d94cba36430055680066bf471d807f`
- Reviewed: 2026-11-17 (by reading the code; the tests were not run here)

**Verdict: Fix first** (one small fix: a wipe late in a mission now pays nothing).

## What it does

Before, the Warden (the boss) came after the main objective was finished, as a separate stage.
Now he comes partway through the main objective and is part of it: the mission is done only
when the work is finished and he is dead, and then the squad goes straight to extraction.

## Findings

1. **A squad that wipes after finishing the work now gets "loss" (0 merits) instead of
   "partial" (60)** (sure). The run's reward reads `primaryDone`
   (`src/server/RunManager.luau:364`), which is set only inside `ObjectiveService.onComplete`.
   With the Warden on, that fires only when the work is done **and** he is dead
   (`src/server/ObjectiveService.luau:390-406`). Before this PR, finishing the hold already
   counted. Trigger: finish the hold (or burn all three tents), then die to the Warden. The
   result screen says loss. `docs/LOBBY_MATCH_HANDOFF.md:129` still says "a wipe after the
   Primary = partial". Smallest fix: have ObjectiveService tell RunManager when the work is done
   (a small `onWorkDone` hook) and set `primaryDone` there. Or, if "loss" is what the owner
   wants, update the doc.
2. **With a Warden already up, the act counts him as dead** (sure; only reachable from the dev
   panel today). `IndexService.arrive` refuses to spawn a second Warden
   (`src/server/IndexService.luau:1329`), and `bringWarden` then sets `act.down = true`
   (`ObjectiveService.luau:328-332`), so the mission completes while he is still alive.
   Trigger: press the dev "Warden (from the Gate)" button, then finish the work. Fix: if a
   Warden is already up, mark him as "came" and wait for his death instead.
3. **The Warden dying after the run ended still pays the reward** (possible).
   `onWardenDown` (`ObjectiveService.luau:374`) does not check that the run is still live. If
   a turret or fire kills him after the squad wiped, it still adds the Resupply, drops the
   reward crate and plays the Done line. Fix: return early when the run is not live.
4. Any way the Warden leaves the world counts as a kill (`ObjectiveService.luau:627-629`),
   including the dev "Clear enemies" button. Fine as a safety net; just know it while testing.
5. Small rule issues: `Config.Objectives.Boss.BossFirst` and `.WorkDone` are read directly
   (`ObjectiveService.luau:385, 405`), so one objective cannot override them like the other
   fields; the `boss` table is typed `any`, so a misspelt field is not caught; and
   `boss.EnterMin or 55`, `or 70`, `boss.At or 0.5` repeat Config numbers in code.
6. Old comments now wrong: `RunManager.luau:354-356` ("Primary -> Index when the hold is
   done"), `IndexService.luau:1444` (`onDefeated` "for RunManager only").
7. Possible gameplay risk (needs play): in Secure the Site and Restore Comms he walks into the
   zone and then hunts the nearest soldier, who is standing in the zone, so the hold may be
   blocked most of the time and a solo player may have to kill him first.

Fine: the mission cannot complete twice (each path is guarded); a restart mid-fight resets the
act; the dev "Warden now" button goes through the existing Studio/creator-only check; bots are
never picked as the record carrier; state is per run, not per player; nothing new runs every
frame beyond a cheap progress check. The new rule `Rules/BossAct` has its tests.
