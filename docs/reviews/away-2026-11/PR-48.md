# PR #48: Carrier update: ship sounds, catalog outfits, slung-rifle walk, night vision (built on claude/integration)

- Author: MatthewDuke04 (Nova; branch `nova/carrier-update`)
- Head commit reviewed: `018b536c65045212dc19dbfd59f7693e85cca28f`
- Reviewed: 2026-11-11 (by reading the code; the tests were not run here). Only Nova's own
  ten commits were reviewed (`1dda10c..018b536`, 49 files, about 1,400 lines).

**Verdict: Needs a decision** (it changes how the soldier looks in the match, not only in
the lobby; two small bugs to fix; and it targets `main` with the integration branch inside).

## What it does

In the lobby: ship sounds, crew and desk staff dressed from Roblox's avatar catalog, the
soldier's rifle slung across the chest, a slow walk with a sprint on Shift.
**In the match too:** players and bots now wear a catalog uniform with **each player's own
Roblox avatar head, face and skin tone**, and there is night vision on the N key.

## Findings

1. **Do not press Merge on this by itself.** Like #46, it targets `main` but is built on
   the integration branch (#44): 83 commits against `main`, of which 10 are Nova's.

2. **Decision for the owner: the match soldier is replaced, and shows each player's own
   face.** `src/shared/Config.luau:63-70` turns `Player.Look.Enabled` and `PlayerFace` on,
   and `src/server/PlayerSetup.luau:280-286` then skips the Pike body that is in the game
   today, for players and bots. `docs/OWNER.md` says "No hero characters. Players are
   anonymous soldiers". A player's own avatar head (any size or novelty shape) under the
   helmet is a change to that, and the comment "every player is the same silhouette" is no
   longer true. Headshots are not affected (only Infected heads are checked).
   If the catalog look fails to apply, the result is ignored and the player is left as a
   bare default Roblox figure with no uniform (`AvatarLook.apply` returns false,
   `src/shared/AvatarLook.luau:136-147`); a bot is not spawned at all
   (`src/server/BotService.luau:210-223`). The three outfit pieces are Roblox catalog items
   referred to by number, not the team's own uploads, so they can be removed or moderated by
   their makers. How sure: verified by reading.
   Smallest fix if the look is kept: fall back to the Pike body when `apply` returns false
   (and to the plain rig for bots); or ship with `Look.Enabled = false` until Tien has seen it.

3. **Bug: one failed catalog lookup removes that item from everyone until the server
   restarts.** `src/shared/AvatarLook.luau:52-70`: a failed lookup is stored as 0, and the
   check `if known then return known end` treats 0 as a real answer (in Luau, 0 counts as
   "true"). So one hiccup of Roblox's catalog service drops that piece of clothing from
   every player, bot and lobby figure on that server. Likely in the lobby, which looks up
   about 30 items at once at start. How sure: verified by reading.
   Fix: only store the answer when it is not 0 (`if kind ~= 0 then kinds[id] = kind end`).

4. **Every spawn and respawn in the match now waits on two web calls before the rifle
   appears.** `PlayerSetup.luau:281` (the look) runs before `:287` (attach the rifle), and
   the look asks Roblox for the player's avatar each time with no cache
   (`AvatarLook.luau:84-88`). Until it answers you can shoot but the gun is not visible.
   How sure: the order is verified; how long the wait is was not measured.
   Fix: attach the rifle first, and remember each player's avatar after the first lookup.

5. **Possible: tapping N twice very fast can leave the screen too bright for the rest of
   the session.** `src/client/NightVision.luau:69-79, 98-101`: turning night vision "on"
   adds brightness each time it is applied, and two quick taps can apply it twice while only
   one is removed later. How sure: possible (needs two taps within about 0.1 s).
   Fix: remember whether it is already applied and do nothing if so.

6. **Decision: looped ship sounds in the lobby.** The owner's rule is "No harsh sound. The
   ambience beds were turned off because they hurt my ears". This adds two looped beds, a
   radio loop, a crowd loop, a horn, a locker slam and a PA call every 9-22 s, and crew
   footsteps, on top of the lobby music (`Config.Lobby.Ambience`). Nova's note says the
   clips were picked by description and not yet listened to. The code is clean (it fades
   properly and cleans up); the question is only whether it sounds good.

7. Decision, small: night vision. It only changes the player's own screen (the server does
   not know about it), there is no dark area in the game yet (it will likely white out in
   daylight), and N clashes with no other key. Night-vision goggles are real kit, so it fits
   "grounded", but it is a new feature nobody asked for in the docs.

8. Docs: the history line and two `Config` comments still describe a plate carrier and a
   "buzzcut" that later commits removed (`Config.luau:60`).

Checked and fine:
- Nothing still uses the crew meshes and the generator (`crew.py`) that this PR deletes.
- No new or changed messages between players and server. The lobby sprint only changes the
  player's own walk speed, which is cosmetic there.
- Every call to Roblox's avatar services is protected against errors, and the lobby does
  not wait on them to start; a figure that fails keeps an invisible stand-in so its desk
  still works.
- The lobby's new per-frame code (slung hands, crew walk, soldier animation) cleans up on
  respawn and is light.
